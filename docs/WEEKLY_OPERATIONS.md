# Weekly operations and helper contracts

Run all helpers against a private directory outside the public checkout. They use atomic state files and an operating-system file lock; this protects local concurrency only. For cross-device runs, acquire `editorial/lease.json` in the private repository with a conditional GitHub write, storing run/window identifier and owner. Refresh and checkpoint through conditional writes. If it is held, reconcile the owning run before taking over. Never force a lease or claim a local lock protects GitHub concurrency.

`python scripts/weekly.py /private/run init --start YYYY-MM-DD --end YYYY-MM-DD` creates a pilot by default. Reusing the directory is rejected; resume its saved state. Copy private registry and feedback snapshots alongside it. The runtime's connected GitHub app handles reads and conditional writes; never place credentials in these files.

`add --input records.json` accepts compact metadata, whitelists fields, filters known dates, deduplicates work identifiers and canonical URLs, and bounds screening text. Supply stable work/version identifiers when known. Distinct mirrors must share a work identifier; do not collapse genuinely new studies on similar topics. Canonical URLs alone cannot solve all identity questions. `advance --stage screen` freezes collection. `screen --input decisions.json` requires a decision for every record and short reasons for advancing at most 50. `advance --stage assess` requires complete decisions.

`python scripts/discovery.py validate /private/discovery/registry.json` validates the registry without a run. `python scripts/discovery.py collect /private/discovery/registry.json --run /private/run` performs charged, metadata-only collection. It records route health and a deduplicated compact inventory before admitting candidates. A healthy route must be reachable, parseable, complete for its advertised response, and demonstrably cover the run window. `fresh` is reported separately and does not by itself establish coverage. Crossref creation dates are provisional discovery dates; verify the publisher's first release before selection. The first request to each registered stream uses the registry allowance; source-declared continuation pages use the extra-metadata allowance so pagination cannot displace later registry routes. Exhaustion of either allowance leaves the affected route incomplete. `referrers` are fetched against the search allowance and produce a separate outbound-link ledger. Their article text is neither screened nor treated as evidence.

Each stream defaults to `admission: {"mode":"all"}`. A broad stream uses `{"mode":"signals","min_score":N}`. Signals are mechanical and auditable: external referral, cross-route discovery, early citation, journal linkage, precedential or en-banc status, phase 3 or 4, large enrollment, research-record metadata, Food and Drug Administration regulation, a data-monitoring committee, or multi-site design. These signals determine whether metadata reaches screening; they do not establish quality or substantive relevance. Admission occurs once across the combined inventory, independent of registry order. More than 1,000 eligible records sets `admission_overflow`, leaves the candidate list empty, and creates a technical hold. arXiv requests use a single connection, at least three seconds between calls, and metadata-limited queries; do not retry a rate limit immediately.

**Screening prompt:** Read only each record's `screen_text` and the current private preference instructions. Choose up to 50 by implied significance and relevance, with approximately five uncertain or exploratory candidates. Return an identifier-keyed decision map using `advance`, `lower-relevance`, `routine`, `duplicate`, or `uncertain`. Advancements require a reason of at most 30 words. Do not retrieve documents, discuss their evidentiary merits, infer ideology, or reward publisher reputation.

`fetch --bucket assess --url URL --id ID` reserves a request before retrieval, charges visible redirects, and caches source bytes privately. It returns a cache path only. `excerpt --bucket assess --id ID --input CACHE --offset N --words 600` mechanically extracts text, emits a bounded portion, and logs actual exposed words. For PDFs install `pypdf` from `requirements-editorial.txt`; do not expose full extracted documents to the model. Locate sections mechanically. Use at most three materially different failed access attempts per work.

For tool-based web search or retrieval, first use `reserve --bucket search|metadata|assess|verify|checks --url QUERY_OR_URL [--id ID]`, perform precisely that action, then `finish --ticket N --status ok|failed`. Store the returned content privately. All actual tool text seen by the model counts; the helper cannot retroactively restrict it. Prefer short structured search results and capture source pages through the bounded fetch and excerpt path. For a batch reserve each underlying action individually. Helper networking has no browser-login capability and does not bypass access controls.

**Assessment prompt:** For each selected work inspect at most 600 words of informative source passages and record `status`, `evidence`, `scope`, `finding`, `limitations`, `source_characteristics`, and `decision`. Identify actual measures and inferential limits. Do not judge novelty by surprise. Do not use a publisher's name as evidence quality. For failed access use `status: access-failed` and a concrete reason. Each record must be at most 350 words. Save with `assess --id ID --input assessment.json`. `advance --stage verify` requires a record for every advanced work, including unresolved failures.

**Verification prompt:** Inspect final candidates and already-assessed reserves within the verification allowance. Record `status: verified`, passages, release_date, first_release_date, document_url, and claims_checked. Confirm chronology and every numerical or substantive assertion. For a revision also confirm the original's current upvote and identify changes. Save with `verify --id ID --input verification.json`, then `advance --stage ready`. The unpublished pilot remains private. Invoke Python `weekly.publication_gate(run, edition, current_feedback)`; it counts validation attempts and reports `may_publish: false` for pilots. Save the drafted edition outside the public checkout before gate execution. The gate validates structure and evidence links; an agent semantic privacy check remains necessary.

`audit` reports actual stage counters and route health. Complete the private coverage map with the major-source safety net, the usable-pool result, failures and truncation, a `complete` boolean, and `shortfall: editorial|technical`. Completeness is an editorial adequacy judgment, not a claim of exhaustive enumeration and not an automatic inference from candidate count. An auxiliary route failure remains logged but does not create an edition-level hold unless it threatens the safety net or the usable pool. Snapshot `run.json` after each stage to `editorial/runs/WINDOW/run.json` on the private branch. Do not reset counters if a run is interrupted.

Registry shape: `schema_version`, `streams` array, and optional `referrers` array. Each stream has identifier, publisher, name, category, source type, endpoint, adapter, homepage, scope, status, date semantics, alternative routes, provenance, last check, and an optional admission policy. A referrer has identifier, name, feed endpoint, status, and provenance. Keep personalization and provenance private. Review upvotes after each run to add narrow streams, then validate routes. Feed and Atom extraction uses `weekly.feed_records`; bounded structured JSON or HTML indexes need source-specific parsing checked against actual records. Collector output must not include full abstracts or invented findings. Maintain 20 rejected metadata examples for user review without extra reading. Record `reachable: true, parsed: false`, pagination tokens, unbounded HTML listings, and admission overflow as route-level technical shortfalls; only admission overflow or a material safety-net failure necessarily holds the edition.

Before publishing, inspect the current private lease and public head. Use ordinary GitHub conditional writes, then record the commit SHA privately. Check its workflow outcome and fetch live edition HTML or data to match window and item identifiers. Pilot tests can validate rendering with fixtures but must not claim a live editorial publication. A failure after commit is reconciled on resume, not retried as a new edition.
